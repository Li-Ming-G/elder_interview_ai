# DISC-005D｜安全结束页产品体验讨论

## 基本信息

- 状态：`READY`
- 负责人：项目负责人 + 安全结束体验讨论任务
- 前置依赖：DEV-005A、DEV-005B、DEV-005C PASS
- 交接对象：总控 Agent、DEV-005D 前端实现任务

## 目标

在不重开已经通过的 stop/recover 服务端契约、不实现代码的前提下，明确倾听员从点击“结束访谈”到安全离开页面期间看到什么、能做什么，以及怎样理解录音与转录的独立结果，使 DEV-005D 不需要自行猜测产品行为。

## 必须讨论并形成决定

1. 点击结束是否确认，以及如何说明结束后不能继续本次录制；
2. `stopping` 时是否必须保持页面打开及对应提示；
3. `processing` 时录音已安全保存、转录仍在收束，是否允许离开；
4. 页面主结论优先表达录音安全，还是整个访谈处理结果；
5. `drained|degraded|not_started` 的通俗文案；
6. `failed` 时展示哪些已保存事实和下一步动作；
7. 刷新、短时断网和重新登录后的返回位置；
8. “完成并离开”的真实目标；
9. 当前没有完整回顾页时，“查看本次记录”如何处理；
10. 各状态下允许的操作和可观察验收场景。

## 不可改变的正式边界

- 页面只消费统一 session snapshot，不自行推算 `completed`；
- `stopping` 表示仍在等待承诺范围内的录音分片或 manifest；
- `processing` 表示原始录音已完整，转录仍在收束；
- `completed + degraded|not_started` 不是录音失败，也不是全链路成功；
- `failed` 是需要人工处置的终态，不承诺普通一键重试可以修复；
- 不提前实现项目列表、完整回顾、导出、删除、AI、真实麦克风或生产能力。

## 讨论方式

- 讨论 Agent 一次只推进一个关键决定，用通俗语言解释差异；
- 每个决定最多给三个方案，明确推荐方案、代价和适用条件；
- 用户未确认时不得把建议写成决定；
- 用户说“讨论完成”或“定稿”后，只在聊天中输出候选决定包，不修改文件、代码、任务状态或 Git。

## 候选决定包

讨论窗口最终必须提供：

1. 页面目标和用户最关心的问题；
2. 从点击结束到终态的页面流程；
3. 每种服务端状态的标题、说明、状态明细和动作；
4. 录音与转录组合结果的通俗文案；
5. 必须留在页面与可以安全离开的时机；
6. 路由、刷新恢复和重新进入规则；
7. 两个终态操作的真实目标；
8. 明确不做；
9. 仍待验证或待决定；
10. 可被 Chromium 直接观察的验收场景。

## 总控验收

总控检查候选决定是否符合 `01/03/05/06/09`、是否越过当前 MVP 范围、是否存在死按钮或错误事实、是否覆盖失败与恢复。只有总控验收通过并写回正式依据后，DEV-005D 才能重新转为 `READY`。
