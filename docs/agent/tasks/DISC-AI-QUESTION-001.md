# DISC-AI-QUESTION-001｜单问题更新、换题与一层撤销体验收口

## 基本信息

- 状态：`IN_PROGRESS`
- 负责人：项目负责人 + 独立产品讨论任务
- 前置依赖：SPEC-FE-001 DONE、DISC-006 DONE、SPEC-DEV-006 DONE
- 输入依据：`01`、`03`、`05`、`07`、`09`、ADR-020/024/026/027、CON-018、SPEC-AI-QUESTION-001
- 交接对象：总控 Agent、SPEC-AI-QUESTION-001、DEV-007

## 目标

只冻结倾听员能感知的“当前一个问题”体验，使后续契约 Agent 无需猜测页面何时更新、换题期间显示什么、没有合格新问题时如何降级，以及一层撤销何时失效。

## 已冻结、不得重开

- 同时只显示一个问题和一句原因，或“继续倾听/AI 暂不可用”；
- 不恢复采用、已问、忽略、稍后或改写按钮；
- 换题中保留旧问题，成功后才切换；
- 一层撤销只恢复最近一次被换掉的问题、原因和该次排除集合；
- 普通修正不自动撤下已展示问题，硬安全边界必须即时隐藏正文且不自动生成替代；
- AI 失败不回退基础题、不无限后台重试，录音和转录继续；
- QuestionEvidenceModule、current memory、actual-question catalog、provenance、retention 与删除边界已经由 SPEC-DEV-006 冻结。

## 必须讨论

1. 已显示问题何时允许被后续谈话自动替换，怎样平衡“跟上话题”和“屏幕不乱跳”；
2. 连续点击“没用，换一个”时，请求进行中、成功、失败分别看到什么，何时允许再次点击；
3. 当新结果与当前问题、真实问过问题或刚换掉的问题过于相似时，页面应该怎样表现；
4. 一层撤销是否需要时间倒计时，还是仅在后续自动更新或 session 状态变化时失效；
5. 用哪些手机/桌面虚构场景验收上述行为，且不增加倾听员认知负担。

## 禁止讨论

- 数据表、REST/WS 选择、request ID、锁、事务、状态码或相似度算法阈值；
- 重新讨论 DEV-006 的记忆、跨会话 provenance、retention 或 actual-question 所有权；
- 记忆管理 UI、多候选问题、基础题回退、真实供应商、完整回顾或自动传记；
- 修改代码、数据库、正式规范、Git 或任务状态。

## 完成条件

项目负责人逐项确认并明确“定稿/讨论完成”后，讨论任务输出：

1. 已确认的用户可观察行为；
2. 未决风险和留给 SPEC 的技术自由度；
3. 对 `01/03/05/07/09`、CON-018 与 SPEC-AI-QUESTION-001 的精确写回建议；
4. 明确本讨论未修改仓库、未实现功能，也未使 SPEC 或 DEV-007 自动完成。
