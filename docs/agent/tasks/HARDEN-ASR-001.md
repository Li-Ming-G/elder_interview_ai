## 目标

在不覆盖原始录音和原始转录的前提下，持久表达实时 ASR 无法恢复的时间区间，并从完整原始录音幂等生成、合并来源为 `backfill` 的确定态转录。该任务属于可靠性加固，不阻塞当前内部可用 MVP、DEV-006 或 DEV-007。

## 允许修改

- 经专项契约审查通过后的故障区间数据模型、内部任务/API、供应商适配器和状态展示；
- backfill 来源、幂等 ingest key、与 realtime final 的去重/冲突规则；
- 真实供应商故障注入、离线补转录与回顾/导出一致性测试；
- 必要的任务队列只能在出现真实后台消费者后按 ADR 引入。

## 禁止修改

- 覆盖原始音频、原始 final、原始说话人角色或授权记录；
- 以补转录成功作为原始录音安全结束的门禁；
- 在供应商和契约未冻结前提前引入队列、云存储或供应商 SDK；
- 用 fake 结果宣称真实供应商恢复质量通过。

## 交付物

- 先行专项契约：故障区间、状态、幂等、权限、审计、合并与失败语义；
- 可追溯 backfill 任务与结果，所有输出回链 audio/session/gap 和原始证据；
- 用户可见的待处理、处理中、成功、失败状态；
- 自动测试、真实供应商故障注入报告和交接记录。

## 验证与验收

- ASR 中断时原始录音、archive、上传和 manifest 不受影响；
- 同一 gap 重试不重复生成片段，不覆盖 realtime final；冲突失败关闭并可审计；
- 权限、授权撤回、删除 scope 与普通/受限读取遵循正式治理规则；
- 进程故障后任务可恢复，失败不伪造成功；
- 项目负责人绑定最终 GitHub head 明确 PASS 后才可 `DONE`。
