## Goal

Make generation publication authority explicit and race-safe so stale or late work can never overwrite a newer interview state.

## Scope

Implement the accepted generation/basis/publication fence using existing QuestionGenerationAttempt, presentation revision/snapshot, AiJob and Decision Trace authorities.

## Allowed Files / Areas

- `apps/api/src/question-orchestration/**`;
- narrow `apps/api/src/question-evidence/question-presentation*` seams;
- narrow already-accepted Decision Trace metadata/finalization seams;
- focused tests;
- `docs/agent/tasks/P6R-03.md` and PR documentation.

No broad schema migration unless P6R-01 explicitly and mechanically requires one; otherwise stop for Architect correction rather than inventing storage.

## Inputs

- P6R-01 accepted Runtime Orchestration V1 contract;
- P6R-02 accepted trigger/gate runtime;
- existing durable attempt/job/presentation/trace state;
- accepted P5 one-round evidence integration.

## Required Behavior

1. Each generation has stable request/attempt/generation identity.
2. Publication revalidates current presentation authority immediately before durable write.
3. A result based on an older presentation revision/snapshot cannot publish over newer state.
4. A newer manual-next accepted basis fences an older automatic generation.
5. Late Director/evidence/provider results may finalize diagnostic state but cannot mutate current presented suggestion/history.
6. Retry/replay of the same identity remains idempotent.
7. Reusing one idempotency key with a different session/actor/basis/context authority fails closed.
8. Fence loss produces explicit stale/superseded publication outcome; it must never be mapped to `CONTINUE_LISTENING`.
9. Prior attempts/traces remain auditable; no destructive cleanup or last-write-wins replacement.
10. No second generation/presentation truth store is introduced.
11. Current P5 evidence round shares the same generation authority and cannot escape the fence.

## Explicit Non-Goals

- no trigger policy redesign;
- no deadline/error policy redesign;
- no prompt/provider/model selection;
- no P1–P5 semantic authority change;
- no UI redesign;
- no generic job framework.

## Tests

Focused tests must cover at least:

- automatic A starts, manual B advances basis, A completes late -> A cannot publish;
- two attempts on different bases -> only current authority may publish;
- exact replay remains idempotent;
- mismatched replay/idempotency reuse fails closed;
- evidence-round result arriving late cannot publish;
- stale publication leaves an auditable trace/outcome;
- no QuestionEvidence/current-history corruption after stale completion.

Run targeted question-orchestration/presentation/trace suites, relevant integration tests, API typecheck, ESLint, Prettier and `git diff --check`.

## Completion Criteria

- no adjacent deadline/prompt/provider expansion;
- one PR with exact `ARCHITECT_REVIEW_CONTEXT_V1`;
