# DISC-005-R0｜首次访谈纵向链路重构总纲讨论

## 基本信息

- 状态：`READY`
- 负责人：项目负责人 + 新的总体讨论任务对话
- 前置依赖：DEV-005A/B/C 历史实现与审查证据、DISC-005D 候选决定包
- 交接对象：总控 Agent、后续 DISC-005A-R/B-R/C-R/D-R

## 目标

先从用户结果重新定义“准备 → 正式录音与实时转录 → 安全收束 → 结果展示”这一条首次访谈纵向链路，再决定后续 A/B/C/D 分别讨论和承担什么。当前只形成候选总纲，不修改旧 DEV-005A/B/C/D、正式产品/技术规范或业务代码。

## 已验证现状

- DEV-005A 已完成准备页和正式路由，但设备检查后释放麦克风，不创建正式访谈录音作业；
- DEV-005B 已完成正式工作台的合成 PCM 实时转录展示，但不接真实麦克风、MediaRecorder 原始录音或 stop/recover；
- DEV-005C 已完成服务端 stop/recover，首次 stop 必须收到唯一 interview audio object、冻结分片总数和逐片 commitments；
- 可靠录音/上传作业目前由内部 audio harness 组装，正式工作台尚不能按 session 持有或恢复同一作业；
- DISC-005D 已产生有价值的结束体验候选结论，但必须在新的 A/B/C 技术事实确定后再验收，不提前成为正式需求。

## 必须讨论并形成决定

1. 本轮究竟验证“技术连通”，还是一名倾听员可以实际使用的短时访谈流程；
2. 正式页面的验证等级：真实浏览器麦克风 + 虚构内容、继续合成音频，或直接进入真实供应商/真实试点；
3. 一次访谈从哪个用户动作开始，到哪些可观察事实成立才算本轮结束；
4. 从 start 到 stop，谁持续拥有唯一 session、麦克风流、interview audio upload job 与 realtime stream；
5. 刷新、断网、登录失效和浏览器崩溃后，哪些事实必须恢复，哪些只能明确中断；
6. 录音、上传、转录和 AI 分别显示什么，哪些链路不能代替其他链路宣称成功；
7. DEV-005R 完成与“AI 追问价值已经验证”、真实试点通过之间的边界；
8. 后续 DISC-005A-R/B-R/C-R/D-R 的顺序、输入、输出和跨阶段验收证据。

## 推荐讨论起点

优先评估：正式页面接真实浏览器麦克风，但只使用测试人员和虚构内容；继续使用本地私有存储和内部 ASR seam，真实供应商、长时、云存储和真实长者试点后置。该建议不是正式决定，必须由项目负责人在讨论中确认或替换。

## 不在本轮讨论

- 最终页面文案、颜色、布局、组件拆分；
- API 字段名、数据库锁序、类名和 migration 实现；
- 真实 ASR/LLM 供应商选择、云部署和生产加固；
- 项目列表、完整回顾、导出、删除或自动传记；
- 直接修改、废弃或重写旧 DEV-005A/B/C/D 历史记录。

## 不可改变的底线

- 未授权或无 assignment 不得开始；
- 原始录音、原始转录和授权证据不可覆盖；
- ASR/AI 失败不得导致原始录音丢失；
- 页面不得把合成夹具、URL、计时器或本地猜测冒充服务端完成事实；
- 当前仍是内部虚构/脱敏数据 MVP，不对公网开放，不使用真实长者资料。

## 候选决定包

讨论任务最终只在聊天中提交《DISC-005-R0 候选决定包》，至少包含：

1. 本轮用户结果与不验证的内容；
2. 从准备到结束的完整纵向路径；
3. 每条链路采用真实能力、内部 seam 或占位的选择及理由；
4. session、麦克风、录音上传作业和 realtime stream 的生命周期归属；
5. 刷新、断网、崩溃、重新登录和授权变化后的原则；
6. A-R/B-R/C-R/D-R 各自需要讨论的问题、输入和交接事实；
7. 本轮完成证据与不得宣称完成的范围；
8. 仍待决定、假设、风险和与当前正式文档的冲突。

## 总控验收

总控只验收候选总纲是否闭合、是否符合探索期优先级、是否保护原始证据、是否让后续四轮讨论有稳定输入。通过后仍不立即修改旧 DEV-005A/B/C/D；先依次完成 A-R/B-R/C-R/D-R，再进行跨阶段一致性验收和统一正式写回。
