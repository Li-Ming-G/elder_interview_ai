# DEV-001｜初始化工程与环境

## 基本信息

- 状态：`BLOCKED`（父任务）
- 负责人：总控 Agent
- 子任务：`DEV-001A`、`DEV-001B`
- 前置依赖：两个子任务完成并通过适用审查
- 分支：子任务使用各自分支
- 提交：待子任务产生
- 交接对象：总控 Agent；因包含认证、权限与工程安全基线，完成后需独立审查。

## 目标

建立可在本地和 CI 重复运行的模块化单体工程骨架，为后续业务任务提供统一的类型、配置、数据库迁移、日志、认证与权限基础，不实现 MVP 业务功能。

- 不把占位机器契约标记为“正式”；
- 不选择或接入真实 ASR、LLM、对象存储供应商；
- 不提交真实密钥、真实录音、真实转录或个人信息；
- 不修改产品范围、状态枚举、安全语义或跨模块契约，除非先完成已批准的契约变更。

## 已确认工程基线

1. Node `>=24.11.0 <25`，开发/CI 固定 `24.18.0`；pnpm `>=11.15.1 <12`，固定 `11.15.1`；
2. 正式采用 pnpm workspace，不引入 Nx/Turborepo；
3. Prisma 7 + Prisma Migrate + PostgreSQL；集成测试使用隔离 PostgreSQL；
4. Vitest、Supertest、React Testing Library、Playwright；
5. 根脚本是权威门禁，默认提供 GitHub Actions 外壳；远端未确认前不宣称远端门禁已启用；
6. 同源 Web 使用服务端不透明会话、Argon2id、HttpOnly Cookie、CSRF/Origin 防护；
7. Redis、BullMQ、Nginx 延后；DEV-001 Compose 只包含 PostgreSQL 开发库和测试库。

详细决定见 `02-项目开发规范.md` 和 `ADR-007` 至 `ADR-010`。

## 交付物

- 可安装、可构建的 workspace；
- Web 与 API 最小启动入口；
- 严格 TypeScript、格式、静态检查和测试基线；
- 配置校验、统一错误格式和 JSON 结构化日志基础；
- PostgreSQL 连接、迁移基线与可重置的测试数据库方式；
- 最小认证和角色权限基础；
- Docker Compose 本地依赖编排与 `.env.example`；
- CI 基础检查；
- 更新后的任务、追踪、决策/冲突和交接记录。

## 验证方式

子任务必须封装并执行以下根命令：

- 依赖从干净检出可重复安装；
- 格式检查、静态检查、类型检查、单元测试和构建通过；
- API 与 Web 最小启动烟雾测试通过；
- 配置缺失时启动明确失败且不泄露敏感值；
- 数据库迁移可执行、可验证恢复；
- 未授权和越权基础场景有自动测试；
- `docker compose config` 通过且不包含真实密钥。

Windows PowerShell 使用 `pnpm.cmd`，避免执行策略拦截 `pnpm.ps1`。

## 验收标准

1. 交付物与 `02` 的模块化单体边界一致；
2. 所有开工前决策均有正式记录，不以执行 Agent 偏好代替；
3. 没有提前实现后续业务范围；
4. 实际验证命令和结果写入交接日志；
5. 认证、权限、配置和依赖安全经过独立审查；
6. 总控复核文档、实现、测试和 Git 提交一致后，才可解除 `DEV-002`、`DEV-003` 的依赖阻塞。

## 当前风险

- 当前机器可读契约均为占位，不足以支持前后端按完整 DTO/Schema 大规模并行；
- DEV-001A 首次依赖和 Playwright 浏览器安装可能需要网络批准；
- DEV-001B 涉及认证与权限安全，必须在实现后独立审查，不能由实现 Agent 自验关闭。
