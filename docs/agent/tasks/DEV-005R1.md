## REV-020 supersede 后的跨 generation P1

- `NO_AUDIO_CAPTURED` 是 session 级零证据结论；`abandonEmpty()` 必须在既有 request→project→session→audio 锁内确认该 session 所有 capture generations 均无 `first_pcm_accepted_at`。
- 任一历史 generation 已接受 PCM，即使当前最新 generation 没有 PCM/Blob，也必须返回 `409 CAPTURE_EVIDENCE_EXISTS`，不得把 session/audio/generation 终结为零证据失败，不得创建 finalization 或改变公共 snapshot。
- PostgreSQL 反例覆盖 gen0 有 PCM→中断→resume gen1→gen1 无 PCM 再中断→abandon gen1；拒绝后 session/audio/finalization 与两代 generation 均保持原事实。
- 最新契约基线 `80ab84f` 已把 `04`、`05` 与 SPEC 同步为 session 全 generations 聚合规则；本实现按该正式依据完成定向修复。

## P1 并发补充验收（2026-08-08）

- 首帧 adapter 接受必须有界；失败或证据持久化失败均不得 ACK、不得留下 `first_pcm_accepted_at`。
- 首证据持久后，后续 PCM 不得重复 Prisma transaction/advisory-lock 路径；adapter 阻塞不得阻塞 stop/revoke 安全收束。
- stop/revoke/report 必须使在途 frame producer lease 失效，提交后不得出现迟到 ACK。
- revoke/report 的幂等 replay runtime cleanup 必须绑定原 generation/audio stream；合法 resume 后不得误杀新 producer，同时保留旧代际崩溃窗口补偿。
