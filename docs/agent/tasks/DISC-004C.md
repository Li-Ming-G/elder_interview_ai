## 目标

冻结说话人校准、失败/跳过、恢复后重新确认、单段/批量修正和下游记忆消费的用户语义，使原始录音不因校准失败被阻塞，同时避免错误角色进入长期记忆或已问问题判断。

## 讨论必须决定

1. 校准目标和用户可观察成功标准；
2. 校准发生在原子 start 前，还是 start 后同一正式 ASR 流内；
3. 失败、跳过与重试时录音、转录和页面如何继续；
4. 刷新恢复形成新 generation / ASR stream 后的重新确认规则；
5. 单段与批量修正的默认范围、确认和失败表现；
6. `elder|interviewer|unknown` 对长期记忆、已问问题识别和 AI 上下文的消费边界；
7. 修正后哪些派生结果需要重新分析；
8. 移动端低负担交互和验收场景。

## 已知边界

- 原始录音优先，ASR 或校准失败不得损害录音保存；
- 正式 provider speaker identity 只存在于原子 start 后的正式 ASR 流，准备页临时麦克风检测不能冒充校准来源；
- 原始说话人角色不可覆盖，人工修正与映射历史追加保存；
- 无法确认时允许 `unknown`；
- 新 ASR 流不得静默沿用旧流 provider speaker ID；
- 当前没有真实 ASR 供应商，不承诺真实分离准确率。
