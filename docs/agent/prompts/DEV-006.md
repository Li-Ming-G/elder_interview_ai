## 目标

用虚构/脱敏数据和 local/test structured fake 建立可运行的后台最小纵向链路：可信 elder final → 可追溯 memory claim/resolution/current view → 跨会话 context snapshot；同时实现共享 QuestionEvidenceModule 基座、会后 actual-question analysis/catalog/evidence、可靠版本发布和 actual-asked reader，为未来 DEV-007 提供唯一正式 seam。

## 必须实现

1. 按 SPEC-DEV-006 final contract 新增 forward-only Prisma migration、约束、索引、枚举和 legacy 失败关闭迁移；不得修改既有 migration。
2. 实现逐 session scope（包含 0 eligible）、segment/memory membership、text/role revision/digest 冻结和 freeze-call-recheck coordinator；供应商调用期间不得持数据库锁。
3. 实现每个独立业务输出一条 `ai_derived_output`、跨表 deferred identity/type/project/job 约束、expected dependency count/manifest 和动态 eligibility reader。
4. 实现 trusted elder memory claim/resolution/current view、冲突共存、明确更正只切未来 current、human-confirmed authority 保护和跨会话 context snapshot。
5. 实现 QuestionEvidenceModule 共享 generation/display/actual-question 表与 service seam，但不实现问题生成、自动替换、manual next、history UI/REST/WS orchestration。
6. 实现会后 actual-question structured fake analysis：仅可信 interviewer final；可靠 catalog 整版发布；degraded/not_started/unknown 维持 unjudged，不覆盖旧可靠目录；只有 current published eligible actual questions 进入 actual-asked reader。
7. 实现三类 retention root：`ai_job`、`question_display_snapshot`、`memory_retention_root`；先 hidden/detach 再幂等清理，失败保持隐藏并可用同 cleanup identity 续跑；技术日志不得复制完整转录/模型输入/敏感正文。
8. 接入当前真实 assignment、consent、project restricted/deleted、boundary/policy revision producer；使用正式 `DeletionScopeReader` port 失败关闭。当前没有 deletion producer/runtime 时，必须明确 `NOT IMPLEMENTED / NOT VERIFIED`，禁止生产 no-op。
9. 提供给 DEV-007 的稳定 current-memory、boundary、QuestionEvidence 和 actual-asked reader/service seam；不得复制第二套 question history。
10. 完成 unit、真实 PostgreSQL integration/auth、migration 空库与 legacy fixture、build/smoke；如新增内部可观察 seam，补最小真实 API/service 测试，不开放客户端可控转录/provider payload 注入口。
