## 已知事实

- 正式录音和 ASR 流只在原子 start 后建立；准备页的临时麦克风检测流不能作为正式 provider speaker identity 来源。
- 原始说话人角色不可覆盖；人工修正使用独立字段；speaker mapping 历史追加保存；无映射时允许 `unknown`。
- 刷新恢复会产生新的 generation / ASR stream，旧流的短 provider speaker ID 不能被假定为新流同一身份。
- DEV-006 长期记忆不能把未确认的倾听员话语误当成长者事实。
- 当前没有真实 ASR 供应商，本轮不讨论或承诺真实声纹、分离准确率或供应商阈值。

## 推荐讨论起点

- 校准不作为原始录音 start 的硬门禁；
- start 后使用同一正式流进行简短角色确认；
- 失败或跳过时录音和转录继续，角色保持 `unknown`；
- `unknown` 不进入依赖角色归属的长期记忆或确定的“已问问题”证据；
- 新 ASR 流需要重新确认；
- 工作台默认单段修正，批量修正必须明确影响范围和段数；
- 永不覆盖 `original_speaker_role`。

上述只是推荐起点，未经项目负责人确认不得视为决定。

## 讨论方式

一次只推进一个问题。每个问题先用通俗语言说明为什么影响真实访谈，再给最多三个互斥方案；推荐方案放第一位，说明用户价值、成本、可回退性和失败表现。不要一次抛出整套问卷。

按顺序讨论：

1. 校准目标和成功标准；
2. 校准时点；
3. 失败、跳过和重试；
4. 刷新/恢复后的重新确认；
5. 单段与批量修正；
6. `elder|interviewer|unknown` 的下游消费边界；
7. 修正后的重新分析；
8. 用户状态、移动端交互和验收场景。

不要让项目负责人决定 PostgreSQL 锁/索引、API 字段名、provider ID 内部命名空间、React 组件拆分、批量 SQL、审计字段或 fake adapter 细节。
