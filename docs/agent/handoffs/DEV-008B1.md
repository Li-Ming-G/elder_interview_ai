## 实现范围

- 新增单一服务端 `RepeatInterviewDecisionService` 与固定首命中 evaluator；Home mapper、next-session、start/replay 和 capture current gate 共用同一 actor/assignment/project/deletion/current-consent/session facts。
- ordinary project 行强制显式投影完整 `repeat_interview` discriminated union；assignment 无效/deleted/soft-deleted 不返回 ordinary row，restricted 保持最小投影。
- 新增 `POST /projects/:id/next-session`：稳定 actor/action/project/canonical-payload binding，`request -> project -> session(id 升序)` 锁序，same-project latest completed basis，非终态 fence，唯一 seq+1；不同 request 并发 loser 稳定返回既有安全 `session_id/sequence_no`。
- next-session 仅创建新的 `interview_session` 与对应 audit/idempotency；不创建或复用 audio object、capture generation、ASR、speaker stream、calibration、consent/audio 或浏览器 local job。
- session/device-check DTO 投影共享 `recording-reminder-v1`；所有正式 start producer 显式提交页面实际显示的版本。start 在创建 audio/capture 前重新检查 assignment、project、deletion、current continuation、device-check、reminder version，并把版本纳入 payload hash；漂移零副作用。
- Home 复用唯一 HomeShell/tokens/routes。next-session frozen request/payload 持久化到既有 IndexedDB 的独立 store；响应未知、刷新/重开与同页 online 使用同一身份重放；已知失败清除旧 attempt，后续只能基于新 server facts 建立新 request。
- 正式重授权只接入 fail-closed 路由 seam：当前无已审查正文/policy 时明确停止，不创建 consent record 或 consent audio。consent create 增加跨 `consent_text_version` 复用同一非空授权音频的拒绝。
- 首访与普通 preparation 都改为先逐值显示服务端 reminder，再由倾听员显式点击“开始访谈”；点击不创建 consent。保留 A4 completion/review/unknown-response 语义。

## 人工审查重点

1. 旧 `/projects/:id/sessions` 是否在 request→project 锁内严格 first-session-only，并保留首次 winner replay；任何已有 session 后是否都无法绕过 `/next-session`。
2. Home、next-session、start/replay、capture confirm/resume 是否确实使用同一 current-facts owner，旧 projection/idempotency/browser cache 是否无法把 unavailable/reauthorization 恢复为 covered。
3. `created` repeat session 是否必须完成当前页 mic/input 与服务端 device-check 才显示 reminder/允许 start；device stream 与 capture stream 是否均为本次全新资源。
4. concurrent loser 的恢复是否只消费服务端 `details.session_id/sequence_no`；stale basis、前 100 行、额外/非法 details 是否绝不触发本地推算或导航。
5. 并发 loser、exact replay、跨 project/basis drift、assignment/restriction/deletion/consent drift 是否保持零新增 session/audio/capture/audit-success 副作用与不泄密错误分类。
6. production/default reader 是否绝无 synthetic 或 `mvp-v1` covered；测试注入是否被 `APP_ENV=test` 与显式开关双重限制。
7. reminder version 是否从服务端 snapshot 逐值展示并绑定 start payload/idempotency，任何缺失或漂移是否发生在 audio/capture/ASR 创建之前。
8. 新 session 是否仅复用 project/consent 的合法业务关系，绝不复用旧 session runtime、labels、audio、idempotency 或 local job。
9. reauthorization seam 在正式正文缺失时是否严格无 consent/audio 副作用；不得把该占位路由认作真实持续授权已可用。
