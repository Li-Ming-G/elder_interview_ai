## 实现范围

1. canonical completed 提交后只发非阻塞通知；稳定 `post-session-analysis-v1` root 派生 memory extract 与 actual-question reconcile 两条有界 trigger/request identity。启动和 5 秒周期 reconciliation 从持久事实恢复，GET/list/WS replay 不触发业务作业。
2. 两 lane 复用 `MemoryService`、`QuestionEvidenceService`、`AiJobCoordinator` freeze/call/writeback、retention 与 eligibility；unknown/degraded 为 unjudged，失败/取消/provider unavailable 为 terminal，不回退 completed、录音或回顾。
3. sequence>=2 consumer 同时等待 calibration terminal gate 与 basis 两 lane terminal。calibration-first 只投影 `waiting_basis_analysis`，request/attempt 均 null，且零 opening job、attempt、Context/provider side effect。
4. 两前置 terminal 后以 consumer + basis analysis trigger + calibration gate 生成稳定 opening request/trigger；重复通知、并发与周期恢复汇聚同一 identity。confirmed gate 的 job scope含 basis+consumer；failed/skipped/unavailable 只含 basis，绝不伪造当前 stream trusted membership。
5. Context 复用现有 current eligible memory、current published/judgeable actual asked、scope/dependency/derived-output owner。basis session 由 scope、analysis identity 由 trigger、lane terminal outcome 由既有 context-builder process version 固化；成功 job 不借用 failure code。
6. opening 复用唯一 Director/Prompt/Schema、QuestionPresentation/QuestionEvidence writer、current/history/REST/WS。policy/provider 前置不可用时写诚实 terminal unavailable attempt，不新增 fallback 基础题、第二 AI、memory UI 或 question history。
7. 系统 trigger 的 rejected/orphaned 作业保留持久 terminal evidence；跨实例只在 30 秒宽限后把无进展 pending/running 判为 restart orphan，避免误杀另一实例正在执行的 provider call。
