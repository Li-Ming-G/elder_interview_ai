## 已实现

1. A1 唯一 `/interviews/new` shell 内形成 project → service term → 正式口头 consent 音频 → consent record → session → prepare/device-check → start 的完整入口；创建 draft 后仍明确提示未就绪。
2. 普通 UI 固定逐项展示 `03` §6.1 告知内容，只创建新鲜 `purpose=consent` 音频并在完整 manifest 后提交 `consent_method=recorded_verbal`、`consent_text_version=mvp-v1`；不暴露 `electronic/written`。
3. 四个 create 的 request ID、canonical payload、attempt state 与服务端响应在首次 fetch 前进入 actor-bound IndexedDB workflow；双击在持久化前即加锁。超时/网络中断标为 unknown，刷新/重开锁定表单并只重放原 ID；ACK 的 project/target/payload/version/status 不匹配失败关闭。
4. 服务端统一保存 actor/action/target-or-project-create-identity/RFC 8785 payload SHA-256 与首次响应快照。首次业务记录、assignment/历史、审计和 idempotency record 同事务；同 ID 异 actor/action/target/create identity/payload 返回 `IDEMPOTENCY_KEY_REUSED`。
5. Prisma migration 为旧记录兼容地增加 nullable `create_identity/request_payload_hash` 并允许 project create 无 target；新写入受 target/create identity 二选一约束。
6. 正式 consent 录音复用既有可靠 chunk/archive/upload job；init/chunk/complete 各自稳定 request identity。刷新可恢复未冻结 job，冻结后禁止重新追加，保存失败只恢复同一 job。
7. start 在 project/session 事务锁内验证当前 assignment、project ready/active、session device_check、当前 service term、最新有效 consent 和 `mvp-v1` 版本；失败不创建 audio/generation/audit/idempotency 副作用。
8. preparation 的 detached session create 同样在 IndexedDB 首次联网前持久稳定 ID，收到权威响应后才清除。
