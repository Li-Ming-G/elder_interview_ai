## 实现结果

- 前向 migration 新增 `session_capture_generation`、状态/时间/跨 session 外键、单 current generation、generation 0 offset、顶层 `capture_failure_code` 终态约束；修复与既有 finalization migration 重复创建 interview object 唯一索引的问题。
- start 使用稳定 `request_id + mime_type + audio_stream_id`，在 request→project→session 锁内原子创建唯一 interview audio object、generation 0 preparing、recording session、审计与幂等响应；interview audio init 改为拒绝，避免第二对象入口。
- 新增 confirm-active、report-interrupted、resume-capture、abandon-empty 的验证、路由、service、contracts 与统一公共 snapshot；capture snapshot 只暴露白名单字段。
- 采用已批准契约修正：无 finalization 的空采集将 session 置 `failed`、顶层 `capture_failure_code=NO_AUDIO_CAPTURED`，finalization 保持 `null`；未扩大失败枚举。
- 第一帧 PCM 由 adapter 成功接受与 `first_pcm_accepted_at` 持久化在 project→session→audio 临界区内串行；持久化失败映射为脱敏 `REALTIME_UNAVAILABLE`，不记录 frame、不 ACK。
- report-interrupted 只允许 active 原 actor 在 assignment 失效后减权报告，disabled actor 失败关闭；stop/finalization 或终态只返回稳定 snapshot，不倒退。
- resume 复用唯一对象、递增 generation，并校验 local archive count、server chunk high-water、前代 timeline offset；新 stream 可安全替换已释放的旧 runtime。
- revoke 与 start/stop/upload/capture 共用固定资源锁序；提交后释放 producer，幂等重放可依据脱敏审计中的首次 session ID 补做清理，不重复业务写入或审计。
- normal stop 将当前 preparing/active generation 置 `stopped` 并统一使用 `SessionSnapshotService`；撤权先到时转为 `auth_lost/interrupted`，不会创建双 finalization 或状态倒退。
