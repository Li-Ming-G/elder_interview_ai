## 实现事实

- Prisma 前向 migration 建立独立 `speaker_stream`、calibration attempt/membership、mapping authority、session revision、transcript content kind/original authority，并以数据库约束保证单 active stream、单 collecting attempt、stream-scoped mapping/membership 和 generation-derived 边界。
- runtime/provider namespace 建立时持久创建 `speaker_stream_id`；仅 transport/event replay 复用同 runtime，真重建关闭旧 stream 并创建新 stream。同名 `speaker_1` 不跨 stream 继承。
- begin/resolve marker 与 producer PCM 共用 `SessionRuntime` 的同一个有界 `CausalQueue`。marker 之前的 work 包含 adapter 返回、final ingestion/membership、业务事件 append 与 ACK 事实；marker transaction 内没有外部 ASR 调用。队列超时或 transaction failure 不产生边界、attempt、幂等或审计半事实。
- final 按同一 speaker stream 的不可变 sequence/session-timeline 半开区间分类；delayed-before、delayed-inside、cross-boundary、after-resolve 与 stream replacement 均由 PostgreSQL integration 覆盖。控制片段保留 original text/role/evidence，但标为 `speaker_calibration`，不进入普通角色消费。
- provider mapping authority 默认 `unconfirmed`。只有 confirm 在同一 transaction 中写入两条 `user_confirmed` mapping，并让 `speaker_role_revision` 恰好递增一次；confirm replay 不重复递增。fail/skip 不停录音、不建可信 mapping，并可显式 retry；confirmed 在 C1 不重新校准。
- GET、begin、resolve、`session.ready` 与 `speaker.calibration.updated` 共用唯一 `SpeakerCalibrationSnapshotService` mapper。WS 前后端同批切换到 1.1；同 request 首次响应、GET 当前事实和 WS replay 原事件事实保持区分。
- Web 复用现有 controller/workbench 和唯一正式 MediaRecorder/getUserMedia/audio object/AudioWorklet/PCM/ASR 链路。小屏状态明确显示“正在录音”，覆盖 collecting/confirmed/failed/skipped/retry，按钮不小于 44px，并保留 focus-visible、live region、alert 和 reduced-motion 约束。
- deterministic streaming fake 仅 local/test 使用：sequence 0 产生 interim 与 `speaker_1` final，sequence 1 产生 `speaker_2` final，sequence 2 失败关闭；production 仍失败关闭，未增加任何客户端 provider label、正文或 provider payload 注入口。
