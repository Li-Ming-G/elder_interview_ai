## 实际实现

- 新增 forward-only Prisma migration：`text_revision`、`ai_policy_revision`、`ai_retention_policy_version`；AI job/session scope/segment-memory membership/provider call；逐业务输出 derived 与 segment/memory/question dependency；memory claim/evidence/resolution/member；QuestionEvidence generation/display/actual 表；context snapshot；三类 retention root 与最小哈希 cleanup audit。
- 数据库用 partial unique、owner check、FK/cascade/detach 策略和 deferred constraint trigger 保证业务 root 与 derived row 的 type/project/job/identity 一致；expected count/manifest 防止依赖删除后 vacuous eligibility。
- `AiJobCoordinatorService` 按 request→project→sorted sessions 固定锁序冻结输入，在事务外调用 local/test structured fake，再以同锁序重检 assignment、最新授权、project、policy revision、session role watermark、逐段 text/role/content/digest 和 memory revision；provider call 期间不持数据库锁。
- current memory 仅消费 trusted elder conversation final；保留历史 claim/evidence；冲突形成 conflict set；明确更正只切换未来 current；human-confirmed current 不被自动结果覆盖，自动结果进入 review-required。
- `QuestionEvidenceModule` 单一拥有 generation/display/actual-question 表和 DEV-007 writer seam；DEV-006 只实现会后 trusted interviewer actual analysis/catalog/evidence/outcome 与 actual-asked reader。unjudged/failed 不发布空目录、不覆盖旧可靠目录。
- context snapshot 只冻结 current/eligible memory 与 current published/eligible actual questions及双 manifest，不开放 UI。
- retention 仅三类 root：先 hidden/detach，再幂等 purge；失败保持隐藏并用同 cleanup identity 续跑；日志只留哈希 root/request、结果、错误码和计数。
- consent append/revoke 在权威事务内递增 `ai_policy_revision`；动态资格仍每次重读 assignment、consent、project 与 deletion port，不把 revision 当授权替代品。
