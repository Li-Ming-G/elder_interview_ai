# 04｜数据模型规范

## 1. 文档职责

本文件是数据库实体、字段、关系、状态枚举和索引的正式契约。

任何表、字段、约束、状态枚举或索引变更，都必须先更新本文件，再修改迁移、代码和测试。REST API 与 WebSocket 契约见 `05-API与实时事件契约.md`。

## 2. 通用约定

- 主键：UUID；
- 时间：ISO 8601，数据库使用带时区时间；
- 金额：最小货币单位或精确数值；
- 软删除：`deleted_at`；
- JSON 字段：PostgreSQL `jsonb`；
- 公共请求追踪：`request_id`；
- WebSocket 事件版本：`schema_version`；
- 所有外部输入必须校验；
- 原始数据与修订数据分开保存。

## 5. 索引建议

- `elder_project(status, updated_at desc)`
- `project_assignment(user_id, revoked_at)`
- `interview_session(project_id, sequence_no)`
- `audio_chunk(session_id, sequence_no)`
- `transcript_segment(session_id, start_ms)`
- `transcript_segment(session_id, finality, created_at)`
- `memory_item(project_id, type, status)`
- `memory_item` 的 `value_json` 建立必要 GIN 索引
- `question_suggestion(session_id, created_at desc)`
- `content_marker(session_id, marker_type)`
- `audit_log(entity_type, entity_id, created_at desc)`


## 6. 数据模型变更规则

1. 新增字段优先保持向后兼容。
2. 删除、改名或改变字段语义必须提供数据迁移方案。
3. 状态枚举变更必须同步业务流程、API 契约和测试。
4. 数据迁移必须提供回滚、补偿或可验证的恢复方案。
5. 任何模型变更都必须同步更新需求追踪矩阵。
